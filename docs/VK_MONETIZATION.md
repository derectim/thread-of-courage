# Монетизация и рейтинг VK

Практический чек-лист для приложения VK `54751080`.

## Реклама

- Все активные таланты работают по одной схеме: игрок сам нажимает кнопку, смотрит rewarded-рекламу и получает одно применение таланта в текущем походе.
- Талант считается использованным только после успешного ответа `VKWebAppShowNativeAds` с `result: true`. Отмена, отсутствие рекламы и ошибка ничего не списывают.
- Для rewarded-рекламы передавать `ad_format: "reward"` и `use_waterfall: false`, чтобы платформа не подменила её обычным interstitial.
- Принудительный interstitial показывать ровно после каждого третьего поражения — только на безопасном переходе после завершения боя. Не показывать при запуске, после победы и между уровнями.
- Если interstitial недоступен или завершился ошибкой, не блокировать игрока. Счётчик поражений всё равно начинает следующий цикл из трёх.
- Соблюдать ограничения платформы: VK может отклонить слишком частый или некорректно размещённый показ.

Официальная документация: [проверка доступности рекламы](https://dev.vk.ru/ru/bridge/VKWebAppCheckNativeAds), [показ рекламы](https://dev.vk.ru/ru/bridge/VKWebAppShowNativeAds), [внедрение рекламы](https://dev.vk.ru/ru/mini-apps/monetization/ad/implementation), [рекомендации](https://dev.vk.ru/ru/mini-apps/monetization/ad/recommendations), [правила Mini Apps](https://dev.vk.ru/ru/mini-apps-rules#5.1.%20Реклама).

## Виртуальные товары

- Завести стабильные SKU, например `cosmetic_chest_01`, и не переименовывать их после запуска.
- Открывать окно покупки через `VKWebAppShowOrderBox`:

  ```ts
  bridge.send("VKWebAppShowOrderBox", {
    type: "item",
    item: "cosmetic_chest_01",
  });
  ```

- Результат клиентского окна использовать только для интерфейса. Он не подтверждает выдачу товара.
- В настройках приложения указать URL платёжных уведомлений, версию API и тестировщиков.
- Сервер должен принимать `get_item`, `order_status_change` и их тестовые варианты, проверять подпись `sig` защищённым ключом и отвечать в формате VK.
- Выдавать покупку только после подтверждённого серверного уведомления. Обрабатывать каждый `order_id` идемпотентно: повторный callback не должен повторно начислять товар.
- До появления такого сервера не включать реальные покупки. Статический GitHub Pages не может безопасно хранить сервисный или защищённый ключ.

Официальная документация: [платежи в Mini Apps](https://dev.vk.ru/ru/mini-apps/monetization/payments), [виртуальные товары](https://dev.vk.ru/ru/api/payments/virtual-goods/vk), [платёжные уведомления](https://dev.vk.ru/ru/api/payments/notifications/vk), [`VKWebAppShowOrderBox`](https://dev.vk.ru/ru/bridge/VKWebAppShowOrderBox).

## Таблица лидеров

- Показывать в игре только имя, аватар, место и максимальный пройденный этап; не делать строки ссылками на профиль.
- Читать общий рейтинг можно через `apps.getLeaderboard` с `type: "level"`, `global: 1` и `extended: 1`.
- Записывать результат только с доверенного сервера через `secure.addAppEvent`: `activity_id: 1` означает уровень, `value` — максимальный завершённый этап.
- Никогда не помещать сервисный ключ в клиентский JavaScript или репозиторий. Клиентское значение `user_result` в нативном окне лишь отображается и не сохраняет результат.
- Сервер принимает только новый личный максимум, проверяет пользователя и защищается от повторных/поддельных запросов.
- Пока серверная запись не подключена, допустимо показывать локальный результат текущего игрока и честно отмечать, что общий список ещё недоступен.

Официальная документация: [`apps.getLeaderboard`](https://dev.vk.ru/ru/method/apps.getLeaderboard), [`secure.addAppEvent`](https://dev.vk.ru/ru/method/secure.addAppEvent), [`VKWebAppCallAPIMethod`](https://dev.vk.ru/ru/bridge/VKWebAppCallAPIMethod), [нативное окно рейтинга](https://dev.vk.ru/ru/bridge/VKWebAppShowLeaderBoardBox).

## Минимальная серверная схема

1. Разместить отдельный HTTPS-бэкенд вне GitHub Pages.
2. Хранить защищённый и сервисный ключи только в секретах окружения сервера.
3. Сделать endpoint платёжных callback VK с проверкой `sig` и журналом обработанных `order_id`.
4. Сделать авторизованный endpoint для фиксации нового рекорда, который вызывает `secure.addAppEvent`.
5. Включить тестовый режим и проверить отмену, повторный callback, отсутствие рекламы, сетевую ошибку и повторную отправку результата.
